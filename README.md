# Universal Meeting Recorder

Записывающее встречи трей-приложение для Windows: C# / .NET 10, WPF. Это порт macOS-приложения ConferenceRecorder (живёт в отдельном репозитории).
Функции те же:
- приложение живёт в трее и детектит любой звонок;
- пишет системный звук и микрофон, сводит их в `recording.m4a`;
- отправляет запись на транскрипцию в Speakr или в НейроМенделеев (выбирается в настройках) и забирает транскрипт и ноуты;
- показывает список встреч;
- напоминает по календарю Outlook, если встреча идёт без записи;
- ведёт задачи в SQLite, извлекает action items через LLM, раз в день присылает сводку;
- даёт кнопку системного mute и виджет задач.

**Форматы на диске совместимы с macOS-версией один в один.** Это папки встреч, `meeting.json`, `transcript.md`, `tasks.sqlite` и JSON задач по HTTP. Совместимость проверяют golden-тесты на настоящих файлах macOS-версии, подробности в разделе «Проверка».

## Структура

```
UniversalMeetingRecorder.slnx
  src/UniversalMeetingRecorder.Core/    net10.0, без Windows API: модели, Speakr, загрузка, задачи, LLM, политики
  src/UniversalMeetingRecorder.App/     net10.0-windows: трей, WASAPI, Outlook, уведомления, окна
  tests/UniversalMeetingRecorder.Core.Tests/   xunit; идут на любой ОС, включая Mac
  tools/publish.ps1, install.ps1, make_ico.py
```

Вся логика без платформы лежит в Core. Это state machine загрузки, сведение и переименование папки (`RecordingFinalizer`), извлечение задач, расписание напоминаний и сводки, детекция звонка по снимку (`MicSessionTracker`). Поэтому она тестируется на Mac. В App остаются только тонкие платформенные адаптеры.

Соответствие файлам macOS-версии:

| Mac | Windows |
|---|---|
| `ConferenceWatcher` (лог `audiomxd`) | `Recorder/MicUsageWatcher` (реестр CapabilityAccessManager) + `Core/Watcher/MicSessionTracker` |
| `SCAudioCapture` | `Recorder/AudioCapture` + `WasapiTrackCapture` |
| `AudioPipeline` | `Recorder/AudioMixer` (NAudio + Media Foundation) + `Core/Audio/MixMath` |
| `RecordingCoordinator` | `Recorder/RecordingCoordinator` + `Core/Meetings/RecordingFinalizer` |
| `SystemMicMuteController` (HAL) | `Recorder/SystemMicMuteController` (IAudioEndpointVolume) |
| `CalendarService` (EventKit) | `Calendar/OutlookCalendarService` (COM) + `Core/Calendar/*` |
| `MeetingReminderNotifier` | `Notifications/ToastNotifier` |
| `KeychainStore` | `Platform/CredentialStore` (Credential Manager) |
| `LoginItemManager` (SMAppService) | `Platform/LoginItemManager` (`HKCU\…\Run`) |
| WidgetKit-виджет | `UI/TaskWidgetWindow` (окно на рабочем столе) + тот же HTTP-фид `127.0.0.1:59731/tasks` |
| `UserDefaults` | `%APPDATA%\UniversalMeetingRecorder\settings.json` (ключи те же) |

## Сборка

Собирается на любой ОС, где стоит .NET SDK 10: благодаря `EnableWindowsTargeting` WPF-проект компилируется и на Mac. **Запускается только на Windows 10 2004+ / 11.**

```bash
dotnet build UniversalMeetingRecorder.slnx
dotnet test UniversalMeetingRecorder.slnx
```

Чтобы получить готовый exe, нужно выполнить шаги ниже. Это самодостаточный single-file с рантаймом внутри, около 85 МБ, .NET на целевой машине не нужен.

```powershell
pwsh tools/publish.ps1          # → dist/win-x64/UniversalMeetingRecorder.exe
pwsh tools/install.ps1          # → %LOCALAPPDATA%\Programs\UniversalMeetingRecorder + ярлык в «Пуск» + запуск
```

На Mac то же самое делается так: `dotnet publish src/UniversalMeetingRecorder.App -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o dist/win-x64`. Получившийся exe переносится на Windows.

Устанавливать нужно через `install.ps1`, а не запускать из папки сборки. От пути exe зависят автозапуск и исключение собственного процесса из детекции микрофона. Скрипт сначала завершает работающий экземпляр, потому что заменять exe под живым процессом нельзя.

Debug-сборку от Release отличают такие признаки:
- она держит настройки в `%APPDATA%\UniversalMeetingRecorder.dev`, а секреты — с суффиксом `.dev` (аналог bundle id `.dev`);
- иконка в трее всегда красная, чтобы не путать её с установленной копией.

Иконка `Assets/app.ico` — производный файл от генератора иконки macOS-версии (`generate_app_icon.swift`). Править нужно генератор, затем выполнить `python3 tools/make_ico.py <путь к AppIcon.appiconset macOS-версии>`.

## Релизы

Сборку и публикацию делает GitHub Actions (`.github/workflows`):
- **CI** — сборка и тесты на каждый push в `main` и на pull request'ы.
- **Release** — по тегу `vMAJOR.MINOR.PATCH` собирает самодостаточный `UniversalMeetingRecorder.exe`, кладёт его в zip вместе с README и `install.ps1` и публикует в GitHub Releases вместе с SHA-256. Версия берётся из тега; тег с суффиксом (`v1.2.0-beta1`) помечается как pre-release.

```bash
git tag v1.0.0 && git push origin v1.0.0
```

Чтобы установить: распаковать zip и запустить `pwsh install.ps1` (по умолчанию он ищет exe в `dist/win-x64`, поэтому укажите `-Source .\UniversalMeetingRecorder.exe`).

## Где что лежит

Переименование в Universal Meeting Recorder не тронуло то, что связывает приложение с macOS-версией:
- папку данных `Documents\ConferenceRecorder` (`AppSettings.SharedDataFolderName`), чтобы записи и задачи можно было держать в одной синхронизируемой папке;
- форматы файлов и имена ключей настроек;
- порт и токен HTTP-фида задач.

Всё остальное (exe, настройки, журналы, секреты, автозапуск, уведомления) называется по-новому.


| Что | Где |
|---|---|
| Записи | `%USERPROFILE%\Documents\ConferenceRecorder\recordings\` (настраивается; имя папки намеренно как у macOS-версии — см. ниже) |
| Задачи | `%USERPROFILE%\Documents\ConferenceRecorder\tasks.sqlite` |
| Настройки | `%APPDATA%\UniversalMeetingRecorder\settings.json` |
| Ключи Speakr/LLM | Диспетчер учётных данных → Учётные данные Windows → `com.monster.UniversalMeetingRecorder.Speakr:apiKey`, `…LLM:apiKey` |
| Журнал | `%LOCALAPPDATA%\UniversalMeetingRecorder\logs\app-ГГГГММДД.log` (в настройках есть кнопка «Открыть папку журналов») |

В отличие от Mac, лог здесь обычный файл и читается. Важные для пользователя ошибки всё равно пишутся в `meeting.json` и показываются в UI.

## Неочевидное и грабли

**Детекция звонка.** Windows сама ведёт учёт приложений, держащих микрофон. Он же питает значок микрофона в трее и раздел «Конфиденциальность → Микрофон → Недавняя активность».
- Где лежит: `HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone`.
- Как понять, что приложение держит микрофон сейчас: `LastUsedTimeStop == 0` при ненулевом `LastUsedTimeStart`.
- Где искать: обычные exe лежат в `NonPackaged\<путь, где \ заменён на #>`, пакеты (новый Teams) — по имени пакета.
- Опрос раз в секунду.
- **Собственный exe исключается обязательно.** Наш WASAPI-захват микрофона тоже попадает в этот список, и без фильтра запись держала бы сама себя бесконечно.
- Имя встречи берётся из описания exe («Zoom Meetings», «Google Chrome»), запасной вариант — имя файла.
- Исключения сравниваются подстрокой и с именем, и с путём.

**Loopback молчит в паузах. Это аналог бага с ускорением ×2 на Mac.** WASAPI loopback не отдаёт пакетов, пока система ничего не играет. Системная дорожка оказалась бы короче реального времени, и выравнивание с микрофоном поехало бы на сумму всех пауз. Против этого две меры, обе в `AudioCapture`:
1. На всё время записи на устройство вывода играет тишина (keep-alive `WasapiOut`).
2. Разрыв между QPC-временем пакета и ожидаемым концом записанного (больше 100 мс) заполняется нулями.

Вторая мера покрывает и смену устройства посреди звонка. Любые правки захвата нужно проверять записью с длинными паузами и сверкой длительности файла с реальным временем.

**Смещение дорожек.** `micStartOffset` равен разнице QPC первых пакетов микрофона и системы, это прямой аналог разницы PTS на Mac. Без него звук собеседника из динамиков, попавший в микрофон, слышен как эхо.

**Формат сырого файла фиксируется первым пакетом.** Он сразу пишется в `meeting.json`: `micSampleRate`/`micChannels` и, только на Windows, `sysSampleRate`/`sysChannels`. Системная дорожка здесь не всегда 48 кГц/стерео, бывает 44.1 кГц или 5.1, а 5.1 сводится в стерео при записи. Если устройство сменилось на другое с другим форматом, новые данные приводятся к уже записанному формату (`FormatAdapter`). Mac незнакомые ключи `sysSampleRate`/`sysChannels` игнорирует.

**Сервис транскрипции — один из двух** (вкладка «Транскрипция»). Новые записи уходят в выбранный; у загруженных встреч в `meeting.json` записан ID того сервиса, где они лежат (`speakrRecordingID` или `mendeleevMeetingId`), и дорабатывает их именно он — переключение ничего не ломает. Что бы ни выбрали, на диске результат одинаковый: `transcript.json` (в формате Speakr — его читают macOS-версия и извлечение задач), `transcript.md`, `notes.md`.

**НейроМенделеев:**
- Публичной схемы API нет: эндпоинты взяты из кода веб-интерфейса (`/api/recordings/upload`, `/meetings/{id}`, `…/transcript`, `…/protocol`), формы ответов проверены на живом сервере. Протокол встречи становится митинг-ноутами, транскрипт приводится к формату Speakr.
- **Вход через SSO без настройки Keycloak.** Это тот же authorization code flow, что у веб-интерфейса, с его `redirect_uri` (`{сервер}/login`), уже зарегистрированным в Keycloak. Приложение открывает встроенный браузер (WebView2), перехватывает переход на `redirect_uri`, забирает `code` и обменивает его на токен через `/api/auth/keycloak-callback`. Токен лежит в Диспетчере учётных данных и продлевается через `/api/auth/refresh`; когда продлить нельзя, вход повторяется.
- Окно входа создаётся за пределами экрана и выезжает в центр, только если вход не прошёл сам за 4 секунды. С Windows-авторизацией (Kerberos) пользователь его не увидит: для сервера входа включается `--auth-server-allowlist`, чтобы Negotiate работал независимо от настроек зоны «Интранет».
- Фоновая загрузка не открывает окно входа чаще раза в 5 минут; кнопка «Войти» в настройках кулдаун обходит.
- Нужен WebView2 Runtime (есть в Windows 11 и в свежих Windows 10).

**Сведение** потоковое (NAudio): ресемпл WDL, задержка позже начатой дорожки, сумма с клипом ±1, AAC 192 кбит/с через Media Foundation. Готовый файл кладётся атомарно, через `recording.tmp.m4a`. В Windows «N» без Media Feature Pack AAC-кодера нет, и тогда встреча получает статус «прервано» с понятной ошибкой.

**Mute** глушит конечную точку устройства ввода по умолчанию **и** устройства связи. Teams и Zoom по умолчанию берут «устройство связи», а оно может отличаться от устройства по умолчанию. Если mute не применился, используется запасной вариант: громкость 0 с восстановлением прежней. Watchdog каждые 0.2 с повторно применяет mute, потому что приложения звонка сами снимают его.

**Outlook:**
- Нужен только классический Outlook. «Новый Outlook» (`olk.exe`) COM не поддерживает.
- Календарь подключается явно, тумблером во вкладке «Календарь»: это аналог выдачи доступа к календарю на Mac. Пока тумблер выключен, приложение к Outlook не обращается.
- Если Outlook не запущен, приложение запустит его в фоне.
- Все COM-вызовы идут на одном STA-потоке.
- `Marshal.GetActiveObject` в .NET 5+ нет, поэтому подключение идёт через P/Invoke `GetActiveObject`.
- Даты в `Items.Restrict` передаются в формате локали пользователя. Точная проверка «идёт сейчас» делается в C# (`OngoingMeetingFilter`), а не фильтром Outlook.
- Чтение описания встречи (`Body`, где обычно лежит ссылка Teams) может вызвать окно Object Model Guard, если антивирус в системе не считается «актуальным».

**Уведомления:**
- Это toast со сценарием Reminder: висит, пока на него не ответят, а кнопки работают через фоновую активацию.
- Звук тоста выключен. Приложение играет свой звук напрямую, чтобы он был слышен в режиме «Не беспокоить», как Frog на Mac поверх Focus.
- Красная рамка — отдельные click-through окна на каждый монитор. Нужен PerMonitorV2 в `app.manifest`, иначе на мониторах с разным масштабом рамка съезжает.

**Один экземпляр.** Второй запуск тихо выходит через именованный mutex. Иначе два детектора писали бы одну встречу.

**Расхождения с macOS-версией (намеренные):**
- Окна собраны кодом (`UI/*.cs`), а не XAML. Так каждое окно читается как порт соответствующего SwiftUI-View.
- Виджет задач — окно на рабочем столе, а не виджет доски Windows 11: тот требует MSIX-упаковки.
- Пункт «Открыть ссылку конференции» и напоминания работают только при подключённом календаре Outlook.

## Проверка

### Автоматически (на любой ОС)

Команда: `dotnet test UniversalMeetingRecorder.slnx`. Помимо модульных тестов, golden-тесты читают настоящие данные macOS-версии из `~/Documents/ConferenceRecorder` (другой путь задаётся переменной `CR_MAC_DATA`; если данных нет, тест молча проходит):
- каждый `meeting.json` после чтения и записи совпадает байт в байт;
- `transcript.md` совпадает с рендером Mac;
- копия `tasks.sqlite` открывается без повторной миграции.

### Вручную на Windows

1. **Детект звонка.** Откройте микрофон любым приложением, например «Звукозапись» или `ffmpeg -f dshow -i audio="Микрофон (…)" -t 30 out.wav`. Иконка в трее должна стать залитой, а в списке встреч должна появиться «идёт запись». Закройте микрофон: запись должна остановиться, свестись и перейти в «короткая» (или в загрузку, если запись длиннее 2 минут).
2. **Длительность и скорость.** Запишите около 3 минут с паузами, когда в системе ничего не играет. Затем проверьте `ffprobe recording.m4a`: длительность должна совпадать с реальным временем, звук не должен быть ускорен, стерео сохраняется.
3. **Эхо.** Включите в динамиках чужую речь и говорите сами: в `recording.m4a` речь из динамиков не должна двоиться.
4. **Смена устройства.** Посреди записи подключите и отключите гарнитуру: запись продолжается, длительность совпадает с реальной.
5. **Восстановление.** Выполните `taskkill /F /IM UniversalMeetingRecorder.exe` посреди записи и запустите приложение снова. Встреча должна пройти путь «прервано» → «сведение» → загрузка. Затем повторите `taskkill` посреди опроса Speakr: после перезапуска опрос продолжается без повторной загрузки (это видно по логу Speakr).
6. **Mute.** Включите оверлей в настройках, начните запись и нажмите Mute: в Teams или Zoom микрофон должен замолчать, в записи — тишина. Если Teams сам снимает mute, через 0.2 с он возвращается. После конца записи mute снимается сам.
7. **НейроМенделеев.** Выберите сервис, укажите адрес и нажмите «Войти»: с Windows-авторизацией окно не должно показываться, без неё — появится форма Keycloak. Затем запишите звонок дольше 2 минут: встреча должна пройти «загрузка» → «обработка» → «готово», в карточке появятся транскрипт и протокол. Проверьте также удаление с сервера (тумблер «Удалять загруженные…») и повторный вход после выхода.
8. **Outlook.** Подключите календарь и создайте встречу «сейчас» с Teams-ссылкой в описании. Ожидаемый результат:
   - сразу приходит toast со звуком и появляется красная рамка;
   - «Отложить на 1 минуту» прячет то и другое;
   - старт записи прячет то и другое;
   - пункт меню «Открыть ссылку конференции» открывает ссылку.
9. **Автозапуск.** Включите тумблер, выйдите из системы и войдите снова: иконка в трее должна появиться.
